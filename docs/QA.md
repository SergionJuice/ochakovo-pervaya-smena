# Проверка версии 4 · 23 октября 2026

## Пользовательские пути

1. **Главный экран → анкета → локальное сохранение:** открытие одним нажатием, вариант «Пока выбираю — хочу обсудить», один email, проверка даты рождения, подтверждение «Анкета сохранена на этом устройстве».
2. **Одно задание → анкета:** неподходящая проба А, объяснение и повтор; подходящая Б, разрешение выпуска. На завершении объяснена профессия; «Хочу на этот участок» сразу подставляет химика-лаборанта. Сохранена тестовая анкета; возврат оставил выполненную лабораторию.
3. **Полная смена → анкета:** лаборатория → датчик → безопасная остановка → специалист → разрешение пуска → склад 4 бутылки кваса + 2 банки Мохито → итог. Выбор кладовщика и открытие анкеты одним нажатием; имитация ошибки не потеряла поля, повторное сохранение успешно.

Дополнительно: анкета во время незавершённой диагностики линии → возврат сохраняет найденный датчик; поля черновика и прогресс сохраняются после обновления; направление редактируется; оплата с пометкой «до вычета налога», график и ночные смены рядом с формой; подробные условия добровольны. Проверены пауза, reduced motion и новая смена. Звук оставался выключенным.

## Сервер и доступ

- Сборка Vinext и TypeScript проходят.
- В отдельном локальном окружении временно включён серверный режим с явно тестовыми получателем, allowlist и текстом, не являющимся юридическим согласием. Через реальный браузер отправлены только вымышленные данные.
- UI показал «Сохраняем…», блокировал повторное нажатие и дождался подтверждения сервера.
- Реальная локальная D1-запись проверена SQL-запросом: одна анкета, `job=keeper`, `entry=finish`, `consent_version=local-test-only`; отдельное событие `application_success` — одно. Это не отправка в компанию и не данные production-базы.
- Временные локальные настройки удалены. `/api/recruitment/config` снова вернул `mode=local`, без получателя и согласия. Hosted-переменные приёма отсутствуют: режим по умолчанию выключен.
- Анонимный браузер не получил `/api/hr/applications`: `authentication_required`. `/team` показал только приглашение войти, без анкет. Allowlist проверен модульно: отсутствующая/чужая идентичность отклоняется, назначенная допускается. Вход реального сотрудника и конечный просмотр после назначения нужно проверить с компанией.
- `tests/recruitment.mjs`: серверная валидация (в том числе неправильные типы и точная граница 18 лет), обязательные настройки активации, deny-by-default, исключение персональных полей из событий, SQLite-запись и подтверждение, повтор с тем же ключом, конфликт изменённых данных, отказ хранилища.
- `tests/save.cjs`: локальная запись/откат, сохранение полей при ошибке, серверное подтверждение, блокировка двойного нажатия, повтор после сетевой ошибки с тем же ключом, отклонение ответа без подтверждённого статуса.
- `tests/validation.cjs`: 14 проверок формы. `tests/packing.cjs`: 6 проверок состава + 9 проверок однозначного добавления/удаления.

## Видео и аналитика

Лабораторный фрагмент запущен вручную: `duration=14`, `readyState=4`, `muted=true`; до нажатия автозапуска нет. Закрытие возвращает к завершённому уровню. Остальные фрагменты перекодированы в H.264/AAC: 12 и 17 секунд. Субтитры описывают видимые действия. Старые длинные MP4 удалены из публичного набора, оригиналы остаются в исходном архиве.

Реальный тестовый визит с `source=university` дошёл через браузерный API в локальную D1; SQL подтвердил категорию источника. Событие успешной подачи создано сервером вместе с записью. События из `?team=1` клиентом не отправляются. В тестах API событий отвергает ФИО/контакт и попытку клиента объявить `application_success`.

## Мобильная проверка и границы

Проверены адаптивные контейнеры **320×568, 390×844, 430×932** в управляемом Chrome. На 320×568 пройдены все три уровня, промежуточные действия, видео, итог и форма; на 390×844 и 430×932 проверены композиция, итог, условия, форма и доступность переходов. Горизонтального переполнения контейнера нет. Кнопки не накрывают предметы; форма и подробные условия прокручиваются. Основные поля — 16 px, клавиатуры `tel`/`email`, нативная дата.

Это проверка адаптивных контейнеров, а не физических телефонов. Настоящая экранная клавиатура iOS/Android здесь недоступна. `visualViewport`, прокрутка активного поля и `interactive-widget=resizes-content` реализованы; аппаратная проверка клавиатуры и браузеров остаётся перед запуском.

Предыдущая версия сохраняла данные только в браузере. Проверка новой серверной записи выполнена отдельно; нельзя представлять существующие локальные анкеты как полученные компанией. Производственные серверные заявки не принимались.
